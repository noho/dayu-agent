# Dayu Research Template Library Plan

## Goal

Build a local, reusable research template layer that reduces the mechanical feel of the existing qualitative report template and prepares Dayu for industry-specific buy-side analysis.

## Phase 7.1 Scope

- Add packaged Markdown templates for common, consumer, cyclical, technology, and financial research paths.
- Add a lightweight `research-template` CLI for listing, previewing, and copying templates into `workspace/assets/research_templates/`.
- Keep the feature local-only and compatible with the existing `write --template` option.

## Non-goals

- Do not rewrite the large default `定性分析模板.md` in this phase.
- Do not change write pipeline semantics yet.
- Do not call external data providers.

## Next Phases

- Phase 7.2: Add template recommendation by ticker/company facets. Done via shared deterministic routing used by `research-template recommend`, manifest materialization, and `write --research-template auto`; first-run auto mode infers facets for the requested ticker before routing.
- Phase 7.3: Let write pipeline optionally compose common + industry templates. Done via both local `research-template compose` and direct opt-in `write --research-template`, with drift protection and the original `--template` path preserved.
- Phase 7.4: Extract monitoring variables from templates into framework rules. Done locally via `research-template monitoring-rules`; generated rules are draft/manual-review JSON until bound to concrete data sources.
- Phase 7.5: Add data-source placeholders to monitoring-rule drafts. Done with template-level candidates and `binding_status=unbound`; no provider integration yet.
- Phase 7.6: Add source-map draft for monitoring data bindings. Done locally via `research-template source-map`; maps candidate sources to Dayu fins tools or external provider placeholders without executing providers.
- Phase 7.7: Validate monitoring rules and source-map consistency. Done locally via `research-template validate-source-map`; returns JSON diagnostics without executing providers.
- Phase 7.8: Add package manifest for template discovery. Done locally via `research-template package-manifest`; summarizes templates, monitoring variables, data sources, and validation results.
- Phase 7.9: Add one-shot materialization for a template bundle. Done locally via `research-template materialize`; writes composed template, monitoring rules, source-map, and package manifest.
- Phase 7.10: Let materialization select from a write manifest. Done locally via `research-template materialize --manifest`; explicit template names still take precedence.
- Phase 7.11: Add a local research guide artifact to materialized bundles. Done via `{template}.research-guide.md`; links the write command, generated artifacts, monitoring variables, and source candidates.
- Phase 7.12: Add a machine-readable descriptor for each materialized bundle. Done via `{template}.bundle.json`; records artifacts, capabilities, automation status, and validation without requiring UI or scheduler consumers to parse Markdown.
- Phase 7.13: Add bundle discovery and independent health validation. Done via `research-template list-bundles` and `validate-bundle`; malformed descriptors remain visible in discovery and unhealthy validation returns a nonzero exit code.
- Phase 7.14: Generate scheduler-readable monitoring execution plans without executing providers. Done via `research-template monitoring-plan`; plans contain stable task IDs, binding readiness, explicit blockers, `execution_mode=dry_run`, and `automated_execution_allowed=false`.
- Phase 7.15: Make persisted monitoring plans independently verifiable and stale-input aware. Done via SHA-256 fingerprints and `research-template validate-monitoring-plan`; normal unbound readiness remains a valid plan, while changed inputs produce nonzero validation.
- Phase 7.16: Add workspace-level plan discovery and dashboard status aggregation. Done via `list-monitoring-plans` and `monitoring-status`; snapshots preserve per-plan diagnostics and prioritize unhealthy plans over blocked or ready states.
- Phase 7.17: Propagate research-target identity through the local workflow. Done via `manifest.config.ticker/company` inference plus `materialize --ticker/--company` overrides; guide commands, bundle descriptors, task IDs, plan inspections, and status summaries retain the target.
- Phase 7.18: Add opt-in recursive discovery and portfolio-level status rollups. Done via `--recursive` on bundle/plan discovery and monitoring status; ticker workspaces remain isolated while the root snapshot reports per-target health and counts.
- Phase 7.19: Add portfolio-manifest batch materialization. Done via `materialize-portfolio`; strict preflight prevents structural partial writes, per-target runtime failures remain auditable, and successful targets produce isolated bundles, dry-run plans, a durable report, and recursive status snapshot.
- Phase 7.20: Add no-write portfolio preview and target-level conflict gates. Done via `preview-portfolio`; exact protected artifacts are classified as create, overwrite, or blocked, and materialization skips conflicted targets before writing any new target artifact.
- Phase 7.21: Export scheduler-neutral monitoring jobs. Done via `scheduler-manifest`; jobs include target, cadence, timezone, plan fingerprint, and validation argv, while remaining disabled and unbound until explicit external approval/binding.
- Phase 7.22: Independently validate scheduler manifests and detect plan drift. Done via `validate-scheduler-manifest`; blocked jobs remain valid, while enabled/bound jobs, rewritten argv, stale fingerprints, live-state mismatches, and summary inconsistencies fail validation.
- Phase 7.23: Add explicit source-binding approval for implemented Dayu tools. Done via `source-bindings`; preview is no-write, applied changes get immutable content-addressed backups, undeclared/external bindings are rejected, and old plans become stale until regenerated.
- Phase 7.24: Add reversible source-binding rollback with audit evidence. Done via `rollback-source-bindings`; only matching content-addressed backups are accepted, preview is no-write, applied rollback preserves the current bound state in an immutable `before-rollback` backup, and plan drift forces regeneration.
- Phase 7.25: Add read-only binding history discovery and snapshot health auditing. Done via `source-binding-history`; current state and both snapshot classes are summarized, invalid fingerprints/templates/source sets remain visible, and unhealthy history returns nonzero.
- Phase 7.26: Make binding rollback itself reversible. Done by allowing `rollback-source-bindings` to restore either trusted snapshot class while preserving the current state before every transition; plan fingerprints force review in both directions.
- Phase 8.1: Convert readable templates into trackable research workbooks. Done via `research-workbook`; actionable sections become stable-ID items with response/evidence/note slots, target identity, source fingerprint, deterministic summaries, preview-by-default, and overwrite protection.
- Phase 8.2: Include workbooks in standard materialized bundles. Done across materialize, guides, bundle descriptors, validation, return payloads, and portfolio conflict previews; existing workbook files require explicit overwrite before regeneration.
- Phase 8.3: Validate edited workbooks and derive live progress. Done via `validate-research-workbook`; structural corruption, duplicate IDs, unsupported states, unsupported answers, incomplete evidence, and template drift fail, while stale cached counters produce warnings plus authoritative live summaries.
- Phase 8.4: Propagate workbook health into bundle validation. Done by deep-validating the referenced workbook and enforcing template/target identity; valid progress warnings remain non-blocking, while workbook errors make bundle discovery and validation unhealthy.
- Phase 8.5: Add safe item-level workbook updates. Done via `update-research-workbook`; item identity is unique, preview is no-write, evidence files append structured records, invalid conclusions are rejected, live counters refresh automatically, and writes preserve immutable content-addressed backups.
- Phase 8.6: Make workbook updates reversibly restorable. Done via `rollback-research-workbook`; trusted same-directory snapshots are identity/fingerprint/health checked, preview is no-write, current bytes are preserved before restore, and the generated redo backup supports exact forward restoration.
- Phase 8.7: Aggregate workbook health and progress across workspaces. Done via `workbook-status`; opt-in recursive discovery preserves per-file target diagnostics, totals only validated item states, exposes corrupt workbooks, and can persist a UI-ready status snapshot.
- Phase 8.8: Make workbook status a standard portfolio materialization output. Done by writing recursive status after each batch, embedding it in the durable report, returning each successful workbook path, and previewing the derived status path; partial failures report only real successful workbook state.
- Phase 9.1: Deepen every template with valuation/expectation-gap and catalyst/timeline analysis. Done with industry-specific assumptions, scenario/downside questions, observable dates, and invalidation triggers; workbooks classify four valuation and four catalyst items per template while preserving existing section IDs.
- Phase 9.2: Add management, governance, and capital-allocation analysis to every template. Done with four industry-specific prompts per template covering guidance history, incentives, investment discipline, stakeholder conflicts, risk culture, and minority-shareholder exposure; workbooks validate them as `management_governance` items.
- Phase 9.3: Connect research conclusions to portfolio decisions and risk budgets. Done with four prompts per template covering edge/confidence, downside and tail loss, liquidity/correlation, opportunity cost, sizing, staged adds/reductions, and exit rules; workbooks validate them as `portfolio_decision` items.
- Phase 10.1: Render validated workbooks into human-readable progress reports. Done via `workbook-report`; deterministic Markdown preserves item IDs, statuses, responses, structured evidence, notes, live counts, and open gaps, rejects invalid inputs, previews by default, and protects existing output.
- Phase 10.2: Make workbook reports independently verifiable and stale-aware. Done with canonical workbook semantic SHA-256 plus Markdown-body SHA-256 metadata and `validate-workbook-report`; formatting-only JSON changes remain valid, content updates become stale, and report edits are detected as tampering.
- Phase 10.3: Aggregate workbook-report freshness and integrity across workspaces. Done via `workbook-report-status`; standard reports auto-pair with sibling workbooks, recursive scans preserve per-file diagnostics, and current/stale/tampered/missing-source counts can be persisted for UI consumers.
- Phase 10.4: Separate workbook/report behavior from the growing research-template command module. Done by extracting the domain into `research_workbook.py` while preserving the existing `research_template` re-exports and CLI behavior through a compatibility test and full CLI regression suite.
- Phase 10.5: Connect named research templates to the production write entrypoint. Done via mutually exclusive `write --research-template`; industry names inject a deterministic `common` + industry deep-research chapter into the official write-template contract, identical workspace artifacts are reused, drifted artifacts fail closed, and the original default/`--template` semantics remain unchanged.
- Phase 10.6: Route write templates automatically from previously inferred company facets. Done via `write --research-template auto`, which reads the current output directory's local `manifest.json`, applies the same deterministic routing rules as `research-template recommend`, falls back to `common` when no industry facet matches, and preserves same-ticker facets across the resulting template-signature migration.
- Phase 10.7: Make first-run automatic routing a single command. Done by bootstrapping an infer-only pass with the official template when auto mode has no local manifest, then resolving the selected write-compatible research template and continuing through the same prepared write service; bootstrap failures and cancellations short-circuit with their original exit codes, while explicit `--infer` remains infer-only.
- Phase 10.8: Persist auditable research-template selection provenance. Done by carrying requested name, resolved name, and named/auto mode through `WriteCliConfig` and `WriteRunConfig` into `manifest.config`, exposing the values in the runtime summary, and preserving backward compatibility for manifests created before these optional fields existed.
- Phase 10.9: Keep downstream research materialization consistent with the completed write run. Done by preferring validated `manifest.config` research-template provenance for both single-target and portfolio materialization, falling back to facet recommendation only for legacy manifests with all provenance fields absent, and rejecting partial, unsupported, or internally inconsistent provenance.
- Phase 10.10: Bind materialized bundles to their source write manifest. Done by persisting the source path, fingerprints, selected template, selection snapshot, and source research target in the bundle descriptor; bundle validation detects missing, invalid, or rerouted source manifests while preserving explicit materialization-time ticker/company overrides.
- Phase 10.11: Distinguish relevant source drift from ordinary write progress. Done with a canonical semantic fingerprint over selected template, selection mode, source target, and normalized company facets plus a separate full-file fingerprint; semantic drift is unhealthy, while chapter/audit-only file changes remain healthy with a warning.
- Phase 10.12: Refresh stale source bindings without destroying research progress. Done via preview-first `rebind-bundle`; writes are allowed only when the current source still resolves to the bundle template, preserve an immutable content-addressed descriptor backup, update no generated research artifacts, validate the candidate and final descriptor, and become a no-op when already current.
- Phase 10.13: Make bundle rebind fully reversible. Done via preview-first `rollback-bundle-rebind`, which accepts only same-directory content-addressed backups matching bundle identity and source path, restores exact bytes, preserves the current descriptor as a redo backup, reports rather than hides an unhealthy restored state, and supports byte-for-byte forward restoration.
- Phase 10.14: Materialize research artifacts directly after a successful write. Done via explicit `write --materialize-research`, with optional root and overwrite controls; the action requires a research-template selection, consumes final manifest provenance, never runs after failed/cancelled writing, and returns a distinct nonzero result when post-write materialization fails.
- Phase 10.15: Make single-target research materialization exception-safe. Done by snapshotting every protected artifact before generation, treating final bundle health as a commit gate, deleting newly created files on failure, and restoring overwritten files byte-for-byte; this is an in-process rollback guarantee rather than a filesystem crash transaction.
- Phase 10.16: Make the human-readable progress report a standard bundle artifact. Done by generating it with every materialized workbook, linking it from the guide and descriptor, validating integrity/freshness as part of bundle health, protecting it in conflict previews and rollback snapshots, and retaining compatibility with older descriptors that omit the optional report entry.
- Phase 10.17: Unify single-target and portfolio workspace initialization. Done via a complete workspace materializer used by CLI materialize, post-write materialization, and portfolio targets; it transactionally adds a validated dry-run monitoring plan, refreshes the guide with plan discovery, preserves the lower-level bundle-only helper, and rolls back bundle plus plan when any late step fails.
- Phase 10.18: Make every initialized workspace immediately dashboard-readable. Done by generating local monitoring, workbook, and report status snapshots after validated plan creation, requiring non-missing/non-unhealthy initial states, linking all snapshots from the guide and return payload, rolling them back with the workspace transaction, and adding recursive report status to portfolio outputs.
- Phase 10.19: Add one-command maintenance for derived workspace state. Done via preview-first `refresh-workspace`, which permits stale/missing report, plan, status, and guide regeneration while blocking invalid workbooks, core bundle failures, and source-manifest drift; `--write` refreshes all derived artifacts under byte-exact rollback and revalidates bundle, plan, and dashboard states.
- Phase 10.20: Close the research-template implementation with a requirement-by-requirement audit. Done when packaged assets are proven in an isolated wheel installation, all documented local CLI/write/workbook/bundle/monitoring/portfolio/refresh contracts pass affected-module static checks and full repository runtime tests, historical deferred wording is reconciled with later completed phases, and no research-template requirement remains open. Repository-wide Pyright findings outside the affected modules remain a separately reported baseline rather than being hidden or attributed to this feature.
